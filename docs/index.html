Enterprise Agent Platform · 代码架构与实现梳理

单仓库 · 前端原生 SPA + FastAPI + SQLite + LangGraph —— 仅收录已落地实现，不含规划/未做项
FastAPI 0.3.0原生 JS SPA（无框架） SQLite + SQLAlchemyLangGraph / LangChain DeepSeek OpenAI 兼容前端 8000 端口单服务托管

0. 一句话总览

一个企业级多 Agent 平台的工作原型：用户在「Agent 工作台」中选择工作区（个人/团队/组织空间）与文件夹，再选择任一可见 Agent 对话；Agent 运行时（LangGraph）携带系统提示词 + 已绑定技能 + 记忆 + 参考材料，通过 9 个工具在该文件夹（工作目录）内读写文件完成产出；平台同时提供「一句话建 Agent」「👍👎 反思迭代」「技能版本化」「多技能工作流」「draft-review 人工审批流」与「用量观测」闭环。

部署形态：本地单进程（uvicorn :8000），一个进程同时托管后端 API 与前端静态文件；数据库为 backend/eap.db（SQLite），工作区文件在 backend/data/workspaces/。

3. 后端 API 全景（已实现 6 组路由）

全部挂载在 /api 前缀下；除 /login 外均需 Authorization: Bearer <JWT>。请求入口文件：backend/app/main.py。

3.1 api_routes.py —— 认证 · 目录 · 记忆 · 用量 · 管理端

方法路径说明
POST/login用户名密码登录，返回 JWT + 用户信息（admin/alice/bob）
GET/me当前用户
GET/agents可见 Agent 列表（org + 同 team + 自有），含默认工作区与 pref（该用户在此 Agent 记住的工作区/文件夹）
GET/memory · DEL /memory/{id}当前用户记忆列表 / 删除
GET/usage/me · /usage/me/recent我的用量聚合 / 最近记录
ADMIN/admin/users · /admin/providers(+toggle) · /admin/agents · /admin/skills(+deprecate) · /admin/usage · /admin/stats平台管理员专用（role=platform_admin）

3.2 api_builder.py —— 技能版本化 · Agent CRUD · 工作流

方法路径说明
GET/POST/PATCH/DEL/skills /skills/{sid}技能 CRUD（scope=private/team/org；作者可编辑）
POST/skills/{sid}/versions · .../versions/{vid} · .../versions/{vid}/publish新建版本 → 草稿可改 → publish 后不可变
POST/skills/{sid}/api · /skills/{sid}/invoke · /skills/{sid}/fork技能 API 化开关 / 调用（可见用户） / 复制为我的私有技能
POST/GET/PATCH/DEL/agents /agents/{aid}Agent CRUD（名/描述/提示词/模型/范围/默认空间/技能绑定列表）
POST/GET/PATCH/DEL/workflows /workflows/{wid}多技能工作流 CRUD（steps=[技能+版本+说明]）
POST/workflows/{wid}/run · GET /workflows/runs/mine运行（executor 顺序串联） / 我的运行记录

3.3 api_flows.py —— Agent 对话（工作区解耦核心）

方法路径说明
POST/agents/{id}/chat核心对话：body={message, refs[], workspace_id?, folder?}；服务端解析工作区 → 注入工作目录说明+参考内容 → 记忆 pref → LangGraph 循环执行
PUT/agents/{id}/ws-pref手动切换工作区/文件夹时立即记忆（下次该 Agent 默认选中）
POST/flows/draft-review · /flows/{run_id}/approve · GET /flows/{run_id|''}多 Agent + 人工审批流（Agent A 起草 → 人工门 → Agent B 评审 / 驳回）

3.4 api_workspaces.py —— 工作区与文件

方法路径说明
GET/workspaces我可见的工作区（个人 + 团队 + 组织），附文件计数与可写标记
GET/workspaces/{id}/files文件树（扫描磁盘，含目录与文件、大小、mtime）
POST/workspaces/{id}/files · GET /download · DEL /files上传（≤50MB，文件名防穿越）/ 下载 / 删除
POST/GET/workspaces/{id}/text文本直接读写（≤2MB 预览；新建/编辑文档）

3.5 api_ai.py —— 生成式构建与反思

方法路径说明
POST/agents/generate-plan一句话需求 → LLM 生成 Agent 蓝图（名称/描述/提示词/agent.md/技能复用建议），不落库
POST/agents/generate-plan/apply蓝图落地：缺的技能建 draft → 绑定 → 创建 Agent
POST/agents/{id}/reflect👍👎+留言 → LLM 反思 → 自动写记忆/为绑定技能建 v_next 草稿或新建技能草稿并绑定/给提示词建议
GET/agents/{id}/reflections反思历史（按 Agent）
POST/agents/{id}/reflect/{rid}/apply-prompt作者/管理员采纳提示词建议（Agent version+1）

4. Agent 运行时与工具（runtime.py + tools.py）

运行时装配（每次对话）

  1. 解析会话工作区：workspace_id（显式，须对用户可见）→ 否则按 Agent 默认空间（workspace_id 绑定 ＞ scope 推导）
  2. build_chat_model：DeepSeek ChatOpenAI 或 Mock；temperature 0.2
  3. build_tools：以「工作区根 + folder（工作目录）」构建 9 工具闭包
  4. 系统提示装配：Agent.system_prompt ＋ 绑定技能指令（skills.load_agent_skill_instructions）＋ extra_instructions（工作目录说明+参考文件内容）＋ 最近 4 条记忆暖启动
  5. create_agent(model, tools, system_prompt) 编译 LangGraph agent；recursion_limit=25
  6. 用量：UsageCaptureCallback 按 token 估算成本写入 LlmUsage；对话记忆自动沉淀（save_memory chat 类型）

7. 关键链路（按代码实际顺序）

7.1 Agent 对话 —— 工作区解耦后的完整路径

  1. 1前端「Agent 工作台」：Agent 记忆恢复 → GET /agents 返回该 Agent 的 pref{workspace_id, folder}，自动选中上次工作位置；用户可切工作区 chips / 点「○」改工作目录 / 「＋」加参考（PUT ws-pref 即时记忆）
  2. 2发送：POST /agents/{id}/chat body={message, refs[], workspace_id, folder}
  3. 3api_flows.chat：可见性校验 → resolve_ws（显式 ws 须可读，否则 Agent 默认空间）→ clean_folder（禁 .. 段）
  4. 4上下文组装：「本次工作区 / 当前工作目录 / 工具路径相对工作目录」 ＋ refs 内容读取（文件全文 ≤200KB 截断、目录给清单）→ extra_instructions
  5. 5set_agent_ws_pref 记忆该位置（下次自动恢复）
  6. 6runtime.run_agent_chat：LangGraph create_agent 循环；工具写文件 → wsvc.upsert_file_record 登记 → 前端消息后自动刷新文件树可见新产出
  7. 7消息气泡附 👍👎 → 差评进入反思链路（7.3）

7.2 一句话创建 Agent

  1. 1generate-plan：需求 + scope + 可选 workspace → LLM 输出 JSON 蓝图（name/description/system_prompt/agent_md/skills[existing|new]）
  2. 2前端预览：技能装配方案（复用已有 or 新建草稿）、可查看 agent.md/系统提示词
  3. 3generate-plan/apply：逐个技能 —— 已存在则复用绑定、不存在则建 Skill(v1 draft)；agent_md 追加进 system_prompt；创建 Agent（scope 决定 owner/team，默认空间可选）
  4. 4跳转工作台对话测试，不满意 👎 触发反思迭代

7.3 反思迭代（reflect）

  1. 1用户对回复点 👍(5★)/👎(1★) 并留言
  2. 2reflect_agent：收集 agent 提示词/绑定技能内容/近期记忆 作为上下文
  3. 3LLM 输出 JSON：analysis + memory_updates(≤4) + skill_drafts(≤2) + system_prompt_suggestion
  4. 4自动应用：写记忆；绑定技能 → 建 v_next 草稿；新技能 → 建草稿并自动绑定（显式 pin 草稿版本）；提示词建议仅落库不自动改
  5. 5作者在反思日志可一键 apply-prompt 采纳建议（Agent version+1）

7.4 draft-review 多 Agent 审批流（orchestration.py · LangGraph StateGraph）

  1. 1start_flow：编译图（checkpointer=SqliteSaver），节点 draft：Agent A 起草（DRAFT_PROMPT）→ 落 FlowRun(waiting_approval)
  2. 2节点 gate：interrupt() 挂起等人工
  3. 3approve_flow：Command(resume={approved,feedback}) 恢复 → 条件路由
  4. 4通过 → review 节点：Agent B 对抗式评审（含反馈），输出 final；驳回 → rejected 节点存档草稿+意见
  5. 5整条流程用量按 kind=flow 计量

8. 权限与安全（实际实现）

可见性规则

对象规则
Agent / 技能scope=org 全员 · team 同团队 · user/private 本人/作者
工作区org 全员；personal 仅 owner；team 仅同 team 成员（读写同权）
工作流scope=private/team/org 同上
管理端require_admin（role=platform_admin）

文件与执行安全

  • 路径穿越防护：workspaces.safe_rel / tools.safe_path realpath 前缀校验，工作区与工作目录双重约束
  • 上传：文件名取 basename、≤50MB、子目录 rel 校验
  • 代码执行：临时目录 + python -I（隔离 PYTHONPATH）+ PATH 白名单 + 30s 超时 + 无网络
  • 密钥：Provider api_key 仅管理端掩码展示（mask_key）；DeepSeek key 由后端持有
  • 技能版本：published 后内容不可变，防线上技能被静默篡改

9. 未实现 / 明确不在此架构内

边界说明（按“只写实际”原则）：无 Docker/容器化与多节点部署；无独立前端构建链（无 npm/webpack）；无对象存储/外部数据库/向量库（RAG 未接入，参考材料为全量文本注入 ≤200KB）；无消息队列与异步 Worker（全部同步请求）；无 WebSocket 流式输出；无 SSO/LDAP（本地 JWT 账号体系）；「多 Agent 协同」目前落地形态 = draft-review 审批流 + 多个 Agent 共享同一工作文件夹协作，尚无编排器式多 Agent 自由协作。
